# 利用ログ

アプリ（`index.html`）が匿名の利用ログを一方通行で送り、Google スプレッドシートに溜める。
集計は同じスプレッドシートの「集計」シートが数式で自動計算する。サーバー代は 0 円。

```
アプリ（各端末） ──ログ──▶ 受け取り係（Apps Script・誰でも送れる・読み出し機能なし）
                                    │
                                    ▼
               スプレッドシート「カラオケ利用ログ」
                 ├ log   … 1行＝1件のログ（受け取り係が追記）
                 └ 集計  … log から数式で自動集計（管理者が見る）
```

- スプレッドシート: https://docs.google.com/spreadsheets/d/1Jq3boKjYm0pzK9tzxSRCb0NPNiTNahLi7TLwpS7DO0k/edit （共有しない＝管理者の Google アカウントでだけ開ける）
- 受け取り係の URL: `logging.js` の `LOG_URL`

## 記録する内容（これだけ）

| 列 | 中身 |
|---|---|
| 受信日時 | Google 側で受け取った時刻（日本時間で表示） |
| 端末ID | 端末のブラウザで最初に開いたときに作るランダムな番号（`localStorage` の `kara-device`） |
| 種類 | `open`＝アプリを開いた ／ `play`＝1回の再生が終わった・止めた・再生中にページを閉じた |
| 再生秒数 | `play` のときだけ。実際に流れた秒数（カウントの4拍は除く） |

- 曲・パート・点数・名前・声・IP アドレスは記録しない
- 利用者側にログイン・許可ダイアログ・設定は一切ない（ブラウザが裏で送るだけ）

## 「集計」シートの見方

- 上の黄色いセル（期間）で 7日／30日／90日／全期間 を選ぶと、上半分が切り替わる
- 上半分: 使った端末数、1日あたりの端末数（平均）、1台あたりの利用日数、開いた回数、合計練習時間、利用頻度の分布（期間中に何日使ったか）
- 下半分: 直近12週の週別、直近30日の日別（端末数・うち初めての端末・開いた回数・練習時間）。こちらは期間の選択に関係なく固定
- K〜O 列は計算用で非表示。**「集計」シートの数式と、`log` シートの見出し行・列の順番は変えない**（集計が崩れる）
- `log` の行を手で消すのは構わない（試しの記録など）

## 自分の試し弾きを数に入れたくないとき

アプリを一度 `…/index.html?nolog` で開くと、その端末からはログを送らなくなる。`?log` で開けば元に戻る。

## 数字の読み方（限界）

- **端末数 ≠ 人数。** 同じ人がスマホと PC で使えば 2、Safari の履歴やサイトデータを消したり、プライベートブラウズで開いたりしても別の端末として数える（多めに出る）。逆に1台を家族で使い回すと 1（少なめに出る）
- 受け取り係の URL はアプリのページを見れば分かるので、形式の合ったデタラメなログを送れてしまう。数字が不自然に跳ねたら `log` を見て疑う
- 再生中にホーム画面へ戻っただけ（ページを閉じていない）の場合は、その後に止めるかページを閉じるまで送られない
- 送信に失敗したログは捨てる（再送しない）。電波の悪い場所の利用は少なめに出る

## 受け取り係のコード（`collector.gs`）を直したとき

Apps Script はコードを保存しただけでは公開中の URL に反映されない。
スプレッドシートの［拡張機能］→［Apps Script］→［デプロイ］→［デプロイを管理］→ 鉛筆アイコン → バージョン「新バージョン」→［デプロイ］で、**同じ URL のまま**更新する。
（［新しいデプロイ］にすると URL が変わり、`logging.js` の `LOG_URL` も直す必要がある）
